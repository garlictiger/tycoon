## Working with this Unity project

There is no CLI build/lint/test pipeline configured in this repo — Unity projects are primarily developed and run from the **Unity Editor** (Unity Hub → open this project with editor version `6000.3.24f1`). Key implications for Claude Code:

- **Editing scripts**: C# scripts can be edited directly as text files under `Assets/`. Unity re-imports and recompiles them automatically when the Editor regains focus — there is no separate manual build step for play-mode iteration.
- **Builds**: Player builds are produced via the Editor's Build Settings (`File > Build Settings`) or Unity's command-line batch mode (`Unity -batchmode -quiet -projectPath . -buildTarget <target> ...`); no build script exists in this repo yet.
- **Tests**: The `com.unity.test-framework` package is installed, but no test assemblies or test scripts exist yet. Unity tests (EditMode/PlayMode) run via the Editor's Test Runner window or `Unity -runTests -batchmode -projectPath . -testResults <path>` in CI/CLI once test assemblies are added.
- **Scenes and assets**: `.unity` scene files, `.asset` ScriptableObject assets, and `.meta` files are YAML/text but are managed by Unity — avoid hand-editing them unless making a small, well-understood tweak; prefer the Editor for structural changes (GameObject hierarchy, component wiring, prefab edits) since hand edits can desync GUIDs/references.
- **Generated/local directories**: `Library/`, `Temp/`, `Logs/`, `UserSettings/`, `obj/` and the `.csproj`/`.sln`/`.slnx` files are Unity/IDE-generated (see `.gitignore`) and should not be edited or committed — they are regenerated by the Editor.
